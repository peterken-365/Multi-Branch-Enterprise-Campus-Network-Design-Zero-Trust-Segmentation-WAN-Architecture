Switching & routing — VLANs, STP, OSPF and the L3 boundary

The L2/L3 skeleton everything else stands on: site-local VLANs with hardened trunks, an explicit STP root, a collapsed core doing inter-VLAN routing, and one OSPF area 0 across the routed WAN. Design docs: l2-switching-design.md · ospf-routing-design.md.

STP plan: MLS-HQ-CORE is root primary for VLANs 10, 20, 30, 40, 99 and 999. SW1 is root secondary for 10/20/40/99, SW2 for 30. Every trunk is 802.1q, native vlan 999, nonegotiate, with explicit allowed vlan lists — so a rogue switch sees a dead native VLAN and DTP never renegotiates.

Layer-3 design

The collapsed core owns the HQ gateways; the routers own the WAN and the Internet edge. Two routed point-to-point links carry OSPF area 0:

AdjacencyLinkSubnetRouter IDs
R1 ↔ R2Link A — R1 Gi0/2 ↔ R2 Gi0/010.20.254.0/301.1.1.1 ↔ 2.2.2.2
R1 ↔ MLSLink B — R1 Gi0/1 ↔ MLS Gi1/1/110.20.254.4/301.1.1.1 ↔ 3.3.3.3
  • passive-interface default on every router/MLS — only the two transit links exchange routing updates. No OSPF hellos ever reach a user or guest LAN.
  • default-information originate on R1 — the branch and core learn the default route dynamically (O*E2), no static routes outside R1.
  • DHCP relay — one central server (10.20.30.10) behind four helpers, so no per-site DHCP infrastructure.
