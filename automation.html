Automation & cloud readiness — configuration as code

Manual CLI typing does not scale and does not detect unauthorized change. The six golden configs are the source of truth; nightly pulls diff against them and flag drift. Source of truth: automation-brief.md.

Golden configurations as source of truth

The files in 02-switching-and-routing-design/configs/ are the authoritative definition of the network: standardized headers and naming per the hardening standard, version-controlled in Git (every change is a reviewed commit, not an undocumented conf t), and any emergency console change is reconciled back into the golden file within one business day.

Nightly backup + drift check

golden config (Git)  <--  expected state
        | diff
running-config (device, pulled via SSH/Ansible)  <--  actual state
        |
        +--> [OK] no drift            -> retain backup, no action
        +--> [DRIFT] differences      -> page netops; unauthorized change process

The shipped bash script is intentionally dependency-free (plain ssh + diff, SSH key auth to each device's management IP as netadmin). Real excerpt from scripts/backup-and-drift-check.sh:

REPO_ROOT="$(cd "$(dirname "$0")/../.." && pwd)"
GOLDEN_DIR="${REPO_ROOT}/02-switching-and-routing-design/configs"
BACKUP_DIR="${REPO_ROOT}/backups/$(date +%F)"
USER="netadmin"

# device-name:management-ip pairs (see 01-topology-and-ip-plan/topology.md)
HOSTS="R1-HQ-EDGE:10.20.255.1 R2-MOMBASA-EDGE:10.20.255.2 MLS-HQ-CORE:10.20.99.1 SW1-HQ-ACCESS-1:10.20.99.2 SW2-HQ-ACCESS-2:10.20.99.3 SW3-MOMBASA-ACCESS:10.20.99.18"

mkdir -p "${BACKUP_DIR}"
drift=0

for entry in ${HOSTS}; do
  name="${entry%%:*}"
  ip="${entry##*:}"
  outfile="${BACKUP_DIR}/${name}.cfg"

  if ! ssh -o BatchMode=yes -o ConnectTimeout=8 "${USER}@${ip}" \
        "show running-config" > "${outfile}" 2>/dev/null; then
    echo "[FAIL]  ${name} (${ip}) - unreachable or auth problem"
    drift=1
    continue
  fi

  if diff -q "${GOLDEN_DIR}/${name}.cfg" "${outfile}" >/dev/null 2>&1; then
    echo "[OK]    ${name} - no drift"
  else
    echo "[DRIFT] ${name} - running-config differs from golden file:"
    diff "${GOLDEN_DIR}/${name}.cfg" "${outfile}" | head -40 || true
    drift=1
  fi
done

Target host mapping matches the management endpoints table exactly — routers on loopbacks, switches on SVI 99.

SDN readiness model

sdn-rest-api-model.md maps the campus onto the management / control / data plane model used by SDN controllers, and shows the same intent expressed as RESTCONF calls with JSON payloads (GET/PUT on a Cisco-IOS-XE-native interface model). It is a design exercise, not a controller deployment — the value is the intent-vs-config split that a controller later automates.

What automation buys this design

  • Fast recovery: any device can be rebuilt from its golden file + crypto key step in minutes.
  • Auditability: every config change is a Git commit with author and reason.
  • Compliance evidence: nightly diffs prove no unauthorized manual changes — pairing with the NTP/Syslog architecture for time-consistent investigation.
  • Scale-out ready: adding a third site = copy a golden file, change site octets, PR review.
