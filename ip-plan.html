IP addressing plan — VLSM from 10.20.0.0/16

Every segment sized to real demand, not to one convenient mask. Convention: each VLAN owns the 10.20.<VLAN-ID>.0 block, so future growth is a re-masking exercise — no renumbering. Source of truth: vlsm-ip-plan.md (+ CSV export).

Why VLAN 99 is split per site. A Layer-2 VLAN cannot span the routed WAN. Keeping one /27 stretched across HQ and the branch would create a discontiguous subnet advertised from two OSPF routers (broken longest-match). The /28 site-split preserves the documented /27 super-block while every routed boundary stays clean.

Growth headroom (deliberate, structured)

  • VLAN 20 (Finance): /25 today; the full 10.20.20.0/24 block is unused outside it — growth = re-mask the SVI + widen the scope. No renumbering.
  • VLAN 10 (IT): /26 today; /25 or /24 available in the same block.
  • VLAN 40 (Guest): dynamic pool starts at .100 so the lower half absorbs admin/appliance statics without disturbing leases.
  • Branch: VLAN 50 can grow to /24 within 10.20.50.0/24.
  • Site replication: the 10.20.<VLAN>.0 convention leaves room for a future second branch (e.g., Kisumu) to reuse VLAN IDs with new site octets.
  • Cloud: 10.20.200.0/24 and 10.20.254.8/30 are ring-fenced NOW so the Azure S2S project needs zero re-IP. See automation & cloud.
