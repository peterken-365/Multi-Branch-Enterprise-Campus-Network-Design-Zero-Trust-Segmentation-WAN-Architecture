Verification runbook — T-01 … T-07

Seven behavioral tests, in execution order, with the exact commands, the recorded reference transcripts, and the pass bar for each. Source of truth: verification_report.md.

Honest status. The transcripts below are reference outputs recorded from the golden configs (session 2026-03-03, Packet Tracer 8.2 build). Screenshot captures are pending per the evidence checklist. The strongest evidence is the kind you produce yourself: build the lab and run the same commands — every command and its expected result is right here.

How to use this runbook

  1. Complete the build (build guide) and the pre-flight checklist below.
  2. Execute the tests in order T-01 → T-07. Each card lists the exact commands and the pass criteria.
  3. CLI output varies slightly between Packet Tracer and IOS-XE — pass criteria are behavioral (traffic succeeds / is dropped / counters increment), not textual.
  4. Capture evidence per the checklist while state is live, and record results in the summary table at the bottom of the checklist.

T-01 — Inter-VLAN routing: Finance → HQ app server

documented

Objective: prove routed east-west reachability between VLAN 20 and VLAN 30 with the FINANCE-IN gateway ACL enforcing the application-port policy.

PC-FIN01 (10.20.20.x) → SW1 → MLS SVI20 → MLS SVI30 → SW2 → SVL-APP01 (10.20.30.20)

  1. Ping and browse from PC-FIN01 (DHCP lease in VLAN 20).
  2. Confirm the FINANCE-IN counters on MLS: echo and www permits increment, the deny ip ACE stays flat.
  3. Simulation mode, ICMP filter: exactly one L3 hop at the MLS (TTL 128 → 127) — the collapsed core routes, not R1.

blocked by design

T-03 — Edge NAT/PAT: Guest → Internet web

documented

Objective: prove guests get exactly the Internet access the policy allows (DNS + HTTP/HTTPS) through R1's NAT/PAT overload — and nothing more.

PC-GUEST01 → MLS SVI40 → R1 Gi0/1 → NAT/PAT (203.0.113.2) → ISP → 198.51.100.10

  1. nslookup internet.test → 198.51.100.10 (via internal SVL-DNS01, permitted before the isolation deny). Browse http://internet.test → external page loads.
  2. Negative control: ping 198.51.100.10 from the guest → 100% loss. ICMP to the Internet is not in the guest allowlist — intentional default-deny.
  3. Inspect the live translation table on R1 — only non-enterprise outside entries, and no internal→internal NAT entries.
recorded · R1-HQ-EDGE# show ip nat translations

Pass criteria: external page loads from the guest; PAT entry shows the public inside-global address; zero internal→internal NAT entries; ICMP from the guest stays denied.

T-05 — Layer-2 attack response: Port Security & BPDU Guard

err-disable on first signature

Objective: prove rogue devices are stopped at the wall jack, exactly as the security policy promises.

Attack A: rogue hub + 2 MACs on SW1 Fa0/3 (sticky, max 2) · Attack B: rogue switch on SW1 Fa0/5 (PortFast + BPDU Guard)

  1. Connect the rogue hub to Fa0/3 — the port sees 3 MACs against maximum 2 and err-disables on the first violation.
  2. Connect a rogue switch to Fa0/5 — BPDU Guard disables the port before it can influence STP.
  3. Recover: shutdown / no shutdown after removing the rogue device (documented procedure).

Targets: any device mgmt address (example: SW1 SVI99 = 10.20.99.2, SSHv2 only)

documented
