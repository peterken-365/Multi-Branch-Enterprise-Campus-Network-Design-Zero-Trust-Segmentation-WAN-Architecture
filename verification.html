One pass bar per architectural claim

T-01 · Inter-VLAN routing

Finance → HQ application server

Objective: prove routed east-west reachability between VLAN 20 and VLAN 30 with the FINANCE-IN gateway ACL enforcing the application-port policy. Path: PC-FIN01 → SW1 → MLS SVI20 → MLS SVI30 → SW2 → SVL-APP01 (10.20.30.20)

PC-FIN01 + MLS-HQ-CORE
C:\> ping 10.20.30.20
Reply from 10.20.30.20: bytes=32 time=1ms TTL=127
Reply from 10.20.30.20: bytes=32 time<1ms TTL=127
Packets: Sent = 4, Received = 4, Lost = 0 (0% loss)

Browser: http://10.20.30.20  -> Savannah intranet page renders

MLS-HQ-CORE# show access-lists FINANCE-IN
 60 permit icmp 10.20.20.0 0.0.0.127 10.20.30.0 0.0.0.31 echo (4 match(es))
 80 deny ip 10.20.20.0 0.0.0.127 10.20.30.0 0.0.0.31        <- stays flat

Pass criteria: 0% loss; HTTP page loads; FINANCE-IN echo/www permits increment while the deny ACE stays flat. Simulation mode shows one L3 hop (TTL 128→127) — the collapsed core does the routing.

T-02 · Zero-trust isolation

Guest → Internal VLANs

Objective: prove the guest VLAN cannot reach ANY internal destination. Path (attack): PC-GUEST01 → MLS SVI40 ingress → DROPPED by GUEST-IN

PC-GUEST01 + MLS-HQ-CORE
C:\> ping 10.20.20.5
Request timed out. (x4)
Packets: Sent = 4, Received = 0, Lost = 4 (100% loss)

C:\> ping 10.20.30.20       -> 100% loss
Browser: http://10.20.30.20 -> page does not load

MLS-HQ-CORE# show access-lists GUEST-IN
 30 deny ip any 10.20.0.0 0.0.255.255 (8 match(es))

Pass criteria: 100% loss to every internal target; deny counter increments per attempt; deny records arrive on the central Syslog server. Guest DNS still works (permitted before the isolation deny) — by design, and proof the ACL is surgical, not blunt.

T-03 · Edge NAT/PAT

Guest → External Internet web server

Objective: prove guests get exactly the Internet access the policy allows (DNS + HTTP/HTTPS) through R1's NAT/PAT overload — and nothing more. Path: PC-GUEST01 → MLS SVI40 → R1 Gi0/1 → NAT/PAT (203.0.113.2) → ISP → 198.51.100.10

PC-GUEST01 + R1-HQ-EDGE
C:\> nslookup internet.test
Non-authoritative answer:
Name:    internet.test
Address: 198.51.100.10

Browser: http://internet.test -> external web page loads
C:\> ping 198.51.100.10      -> 100% loss (ICMP NOT in the guest allowlist)

R1-HQ-EDGE# show ip nat translations
Pro  Inside global      Inside local       Outside local      Outside global
tcp 203.0.113.2:1025   10.20.40.100:1025  198.51.100.10:80   198.51.100.10:80

Pass criteria: external page loads from the guest; the NAT table shows the PAT entry with the public inside-global address; no internal→internal NAT entries (NAT-PERMITTED excludes them); ICMP from the guest stays denied.

T-04 · WAN dynamic routing

Branch → HQ App Server over OSPF

Objective: prove the Mombasa branch reaches HQ services purely via dynamically learned OSPF routes — no static routes on the branch — while BRANCH-IN enforces the branch policy.

R1-HQ-EDGE + PC-BR01
R1-HQ-EDGE# show ip ospf neighbor
Neighbor ID     Pri   State           Dead Time   Address         Interface
2.2.2.2           0   FULL/  -        00:00:37    10.20.254.2     GigabitEthernet0/2
3.3.3.3           0   FULL/  -        00:00:34    10.20.254.6     GigabitEthernet0/1

R2-MOMBASA-EDGE# show ip route | include 10.20.30.0|0.0.0.0/0
O       10.20.30.0/27 [110/2] via 10.20.254.1, 00:14:02, GigabitEthernet0/0
O*E2 0.0.0.0/0 [110/1] via 10.20.254.1, 00:14:02, GigabitEthernet0/0

C:\> tracert 10.20.30.20
  1   10.20.50.1      R2 Gi0/1.50 (branch gateway)
  2   10.20.254.1     R1 Gi0/2 (WAN edge)
  3   10.20.254.6     MLS-HQ-CORE
  4   10.20.30.20     SVL-APP01 reply

C:\> ping 10.20.20.5        -> 100% loss (Branch -> Finance HARD DENY, logged)

Pass criteria: both R1 adjacencies FULL; the branch holds only dynamic OSPF + default routes; traceroute shows exactly the three routed hops; branch→HQ-server succeeds while branch→Finance stays denied and logged.

T-05 · L2 attack response

Port Security & BPDU Guard

Objective: prove rogue devices are stopped at the wall jack. Procedure A: connect a rogue hub with two extra MACs to SW1 Fa0/3 (Finance, max 2). Procedure B: connect a rogue switch to SW1 Fa0/5.

SW1-HQ-ACCESS-1
%PORT_SECURITY-2-PSECURE_VIOLATION: Security violation occurred, caused by
  MAC address 00D0.9711.2201, on port FastEthernet0/3.

SW1-HQ-ACCESS-1# show port-security interface FastEthernet0/3
Port Status                : Secure-shutdown
Violation Mode             : Shutdown
Sticky MAC Addresses       : 1
Last Source Address:Vlan   : 00D0.9711.2201:20
Security Violation Count   : 1

SW1-HQ-ACCESS-1# show interfaces status | include Fa0/
Fa0/3   FIN/HR ACCESS   err-disabled  20    auto   auto  10/100BaseTX
Fa0/5   FIN/HR ACCESS   err-disabled  20    auto   auto  10/100BaseTX

%SPANTREE-2-BLOCK_BPDUGUARD: Received BPDU on port FastEthernet0/5 with
  BPDU Guard enabled. Disabling port.

Pass criteria: both ports go err-disabled automatically on the first attack signature; logs and counters captured; recovery (shutdown / no shutdown after removing the rogue) demonstrated.

T-06 · Management plane

SSH/Telnet access control — double enforcement

Objective: prove only the IT Admin VLAN can manage devices, enforced at TWO independent layers (gateway ACLs + VTY access-class).

Three source VLANs, one target
C:\> ssh -l netadmin 10.20.99.2    ! from Guest VLAN 40  -> no response (GUEST-IN)
C:\> ssh -l netadmin 10.20.99.2    ! from Finance VLAN 20 -> no response (MGMT-PLANE)
C:\> ssh -l netadmin 10.20.99.2    ! from IT VLAN 10      -> password prompt, session opens

C:\> telnet 10.20.99.2             ! connection refused (Telnet dead everywhere)

SW1-HQ-ACCESS-1# show ip ssh
SSH version 2 enabled

MLS-HQ-CORE# show access-lists GUEST-IN | include (8 match
MLS-HQ-CORE# show access-lists MGMT-PLANE          <- deny counter increments

Pass criteria: guest and finance attempts fail with matching ACL deny counters + Syslog records; IT admin SSH succeeds; Telnet refused; SSHv2 confirmed.

T-07 · Central DHCP

DHCP with relay agents

Objective: prove one central DHCP server (VLAN 30) serves all user VLANs through the relay agents, handing out exactly the planned scopes — with no rogue DHCP possible.

PC-FIN02 + SW1-HQ-ACCESS-1
C:\> ipconfig
IP Address......................: 10.20.20.6
Subnet Mask.....................: 255.255.255.128
Default Gateway.................: 10.20.20.1
DNS Server......................: 10.20.30.12

SW1-HQ-ACCESS-1# show ip dhcp snooping binding
MacAddress          IpAddress        Lease(sec)  Type           VLAN  Interface
0050.56BE.1102      10.20.20.6       86395       dhcp-snooping   20   FastEthernet0/3
Total number of bindings: 1

SVL-DC01 -> Services -> DHCP: pool VLAN20-FIN, allocated count >= 1
Branch PC-BR02: leases 10.20.50.x via the R2 Gi0/1.50 relay
Rogue DHCP offers on an access port: silently dropped (snooping, untrusted)

Pass criteria: all three user scopes hand out planned addresses/gateways/DNS via the relays; snooping bindings populate on the access switches; rogue offers are dropped.
